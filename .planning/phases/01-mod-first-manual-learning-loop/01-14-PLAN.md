## Phase Goal

**As a** learner, **I want** the source and my units beside each other, with add, generate, and start visible, **so that** I can prepare a lesson without hunting down the page.

Discussion: `01-14-CONTEXT.md`. Sketch: `.planning/sketches/01-14-workspace-layout.html`.

<objective>
Apply the sketch to the workspace shell, the unit list, and the generate-to-practice handoff. Leave practice and feedback content alone.
Purpose: UX-01 through UX-08 are layout and disclosure, not a new learning model.
Output: side-by-side preparation, one phrase per unit, explicit stage headers, and a ready state that points at Start Practice.
</objective>

## Layout contract

- Workspace is a `100dvh` column, `max-width` 1120px. The Lesson List page stays as it is. Do not size the preparation row with `52vh` or a fixed pixel height.
- Preparation is `flex: 1 1 0`. Its used height is the space left after the header and the action chrome, not the height of the text. `flex-basis: auto` and `minmax(min-content, 1fr)` are what made the panes grow with the source and the unit list. A `12rem` track is not the floor: two such tracks plus the 12px gap are 396px, and the measured Preparation at 959×700 is 354px.
- `.pane`, `.sourceBody`, and the unit `.list` use `min-height: 0` and the scrollports use `overflow: auto`. They fill their track. They do not expand it. Add and the one-line hint stay in the units pane chrome, above the list.
- `.preparation` uses `overflow: auto` only when its allocated height is less than the sum of the track minimums below. At the two checked viewports that sum fits, so Preparation itself does not scroll.

## Height budget

Root font is 16px. These heights are the current chrome, not a new visual scale.

Units chrome inside one pane: pane padding 24, stage toggle 40, Add 44, hint line 24, two 8px gaps. Total 148px. A unit row is 40px (row padding 8 plus a 32px phrase button). Two rows plus the 4px gap are 84px.

Source chrome is pane padding 24 plus the stage toggle 40, total 64px. One source line is 24px.

Page chrome outside Preparation and the action stack: workspace padding 20, two 8px gaps, header 66 (24px link, 8px gap, 34px title). Total 102px.

Action chrome with Feedback collapsed, including the exercise-type line: three 40px headers, type line 24, ready line 24, the 16px gap between those lines, Start 44, and 8px panel padding under Exercises and under Practice. Total 244px. That matches the measured 959×700 split: 700 − 102 − 244 = 354px for Preparation.

- From 960px the grid has one row, `minmax(188px, 1fr)`. 188px is the units chrome plus one full row. The source pane is the same height, so its body is 124px, about five lines.
- Below 960px the grid has two rows: source `minmax(88px, 1fr)`, units `minmax(232px, 1fr)`, gap 12px. 88px is the source chrome plus one full line. 232px is the units chrome plus two full rows. Sum 332px. The measured 354px allocation leaves 22px, so both tracks fit and Preparation does not scroll. Add stays on screen. The list shows two full rows. The source body shows one full line; the leftover is 22px and is less than a second 24px line.
- Actions are `flex: 0 1 auto` and `min-height: 0`. From 960px, `max-height: calc(100dvh - 188px - 102px)`. Below 960px, `max-height: calc(100dvh - 332px - 102px)`. While the Feedback panel is in that column, the column height is that same cap and only the Feedback panel scrolls. Exercises, including its header and "Exercises are ready.", Practice, and the Feedback header stay `flex: 0 0 auto`. Remove `max-height: min(12rem, 32dvh)`. FeedbackStage markup and copy stay unchanged.

Checked sums:

- 959×700, Feedback collapsed. Preparation gets 354px. Track minimums are 332px. Add and both panes are inside that box. Start stays in the 244px action chrome.
- 1280×520 with Feedback open, and any window that fails the same height test. Inside height at 520px is 418px. Keeping the 188px preparation floor and the 244px action chrome leaves 26px for the Feedback body. That is not a readable panel. While Feedback is open and the viewport cannot also hold a 160px body, the Feedback panel covers the preparation slot and uses that slot's height (about 174px at 520px, about 354px at 959×700). Preparation stays mounted, so the stored text range and the source and unit scroll positions remain. Closing Feedback uncovers the same panes. Add and Start stay in the action chrome. From 960px the test is `max-height: 693px` because 102 + 188 + 244 + 160 = 694. Below 960px, including a width that matches neither `max-width: 959px` nor `min-width: 960px`, it is `max-height: 837px` because 102 + 332 + 244 + 160 = 838. A taller window, such as 1280×800, keeps preparation and the Feedback body on screen together.
- Stage headers are the existing buttons plus a chevron that reflects `aria-expanded`. Collapsed still means the panel is not rendered.
- Exercises is the header. Generate Exercises is only the inner action. After success, or when the loaded generation is restorable, the panel says "Exercises are ready." and the Practice section is expanded. The generate button is not shown as the primary action when the accepted set is unchanged. When the accepted set differs from the restored generation, show Generate Exercises again. Failure copy stays the current strings.
- Draft rows keep Accept. Accepted rows do not render the status word. One text node for the phrase. The selected row shows a 28px button whose visible content is `×` (`aria-hidden`) and whose accessible name is `Remove {phrase}`. Keyboard: the row is a button, Enter selects it, then the cross is a real button.
