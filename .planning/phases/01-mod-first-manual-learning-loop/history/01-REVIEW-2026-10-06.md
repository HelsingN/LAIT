This pass reviews the post-01-12 delta (reopen, practice UX, and same-session retry). The locked rules hold: `corrected` is remapped only for the same learning-unit id and mode, a named target uses the copy at the cursor, the score denominator is the opening pass size, and the typed field starts read-only with autocomplete off. Three robustness holes remain: Try again leaves the answer field writable without a new focus, a second in-flight submit can rewind the session cursor, and the OpenAPI drift test does not bind the HTTP method to the route it checks.

## Warnings

### WR-01: Try again leaves the answer field writable without a new focus

**File:** `frontend/src/registries/renderers/GapFillRenderer.tsx:26-32`
**Issue:** The typed input is `readOnly` until the first focus (`answerEditable` starts false). Submit disables the field while `feedback` is set, but the renderer key does not change, so `answerEditable` stays true. Try again sets `feedback` to null. The effect clears the draft and the selected chip, then the input is enabled with `readOnly={false}` and no new focus. Password managers fill a field when it becomes enabled; the read-only guard was what stopped that on the first paint, and this path skips it. The next item is safe because a new position remounts the renderer.
**Fix:** Re-arm the guard in the same effect that clears the draft.

```tsx
useEffect(() => {
  if (feedback !== null) {
    return;
  }
  setDraft("");
  setSelectedUnitId(null);
  setAnswerEditable(false);
}, [feedback]);
```

### WR-02: A second in-flight submit can rewind the cursor and a double Continue can fail the round append

**File:** `backend/lait/adapters/persistence/repositories.py:419-425`
**Issue:** `submit_attempt` reads `practice.cursor`, then `add_attempt` writes that value back with `stored.cursor = cursor` in its own transaction. `handleSubmit` only sets React state `submitPending`; it has no ref, unlike `handleStart`. Two clicks before the re-render both POST. If the first request has already advanced the cursor, the second `add_attempt` moves it backwards to the stale position and inserts another attempt. `advance_current_item` may then step forward again, so the learner gets a duplicate row. On the last item, two overlapping `practice.advance` calls both see `cursor == position` and both insert `"{session_id}:{start}"`. The loser raises `IntegrityError`, which the practice router does not map, so one Continue shows "Could not continue" after the round was already appended. `add_attempt` also does not check that the session is still open, so a submit that loses the race with Exit still writes an attempt onto the closed session.
**Fix:** Stop moving the cursor inside `add_attempt`. Keep cursor changes in `advance_current_item` only. Guard submit and continue with a ref the way start already does, and treat a duplicate pass-item insert as the already-advanced cursor.

```python
def add_attempt(self, attempt: Attempt, cursor: int) -> None:
    del cursor
    # ... build AttemptRow ...
    with self._session_factory() as session:
        stored = session.get(PracticeSessionRow, attempt.session_id)
        if stored is None or stored.status != OPEN:
            raise PracticeSessionNotFoundError(attempt.session_id)
        session.add(row)
        session.commit()
```

if (submitPendingRef.current) {

submitPendingRef.current = true;
try {
  // existing submit body
} finally {
  submitPendingRef.current = false;

### WR-03: The OpenAPI drift test accepts any method as long as the URL string exists

**File:** `backend/tests/adapters/http/test_openapi_client_drift.py:50-56`
**Issue:** For each operation the test requires `url: '{path}'` somewhere in `sdk.gen.ts`, then requires `.{method}<` or `.{method}(` somewhere in the same file. Those checks are not on the same export. A route whose URL is present but whose call uses the wrong verb still passes when any other operation uses that verb. A drifted `practice.advance` or a future method change can go green. This is separate from regenerating the client.
**Fix:** Slice the SDK from `export const {exportName}` to the next export and assert that slice contains both the URL and the method.

```python
export_at = sdk.find(f"export const {export_name} ")
assert export_at != -1
block = sdk[export_at : sdk.find("export const ", export_at + 1)]
assert f"url: '{path}'" in block
assert f".{method}<" in block or f".{method}(" in block
```
