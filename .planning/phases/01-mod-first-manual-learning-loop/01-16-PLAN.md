## Phase Goal

**As a** learner, **I want to** retry a miss without starting over, see the answer only when I ask, and keep practicing only the items I have not yet corrected, **so that** the saved history still shows the first error and the score is not a cleaned-up first try.

## Locked Rules

These rules are the contract. Do not reopen them during execution.

### Progression

- The first submit of the current item advances the cursor only when the stored category is `correct`.
- An `incorrect` submit inserts one row and leaves the cursor on that item. The chips and the typed field stay disabled.
- The incorrect card shows Try again, Show answer, and Continue. A correct card shows Continue only.
- Try again stays on the same session id and the same item. It clears the grade lock, the typed draft, and the selected chip. It does not POST start-over, does not finish the session, and does not change the cursor.
- A later matching submit is stored as `corrected` only when this same pass item already has an `incorrect` attempt in this session. The cursor then advances by one. The card shows Continue only.
- A match is not `corrected` merely because some attempt exists. A prior `correct` on this item does not qualify. An `incorrect` attempt on the other mode of the same phrase does not qualify. That other mode's first match stays `correct`.
- Another miss on this item inserts another `incorrect` row. The first `incorrect` row stays. The cursor stays. The three buttons return.
- Show answer paints `expected` once. It writes no attempt and does not move the cursor. Try again is removed. The revealed flag is stored in localStorage under the session id and the pass-item position. Reload, return from the lesson list, and a direct URL restore that card with the phrase visible and Try again absent. A miss that has not been revealed reloads as the error card with Try again still available. The flag is not an attempt and does not need a migration.
- Continue after a miss or after Show answer calls `practice.advance` with the position of the item being skipped. In one transaction the command increments the cursor only when that position is still the current item and that item has an attempt. A second call for the same position returns the view at the cursor it already reached and does not skip the next item. A call for a different position, or for an item with no attempt, is rejected.
- On the last item of a round, Continue does not finish the session while the uncorrected queue is non-empty. It starts the next round in the same focus view. Try again is not that finish and is not that next round.
- Exit Practice remains available on every item. It closes the current pass, saves the attempts, shows Feedback, and does not append a round.

### Retry accounting

- Every submit inserts an Attempt. Nothing in this plan updates or deletes an existing Attempt.
- `correct` is stored only when this submit is the first attempt for that learning-unit id and mode in this session and the answer matches. Position is not part of that key.
- `evaluate()` keeps returning `correct` or `incorrect`. `exercise.submit_attempt` remaps to `corrected` only when evaluate() returns `correct` and this pass item, matched by learning-unit id and mode, already has an `incorrect` row in this session. A repeated row at a later position uses the same pair. Gap Fill grading stays an identity compare for drag and the existing typed compare.
- Show answer and Continue write no row.
- Start Over is unchanged: it abandons the open session and mints a new one. Try again is not Start Over.
- Chip order for Try again stays the order already seeded by this session id and this item id.

### Score and repeat queue

This replaces the earlier rule that a later `corrected` item stays in the missed set. The automatic queue contains only items that are still uncorrected.

- Score text is `{first-try correct}/{opening pass size}`.
- The numerator is the number of opening pass items whose earliest attempt in that session has category `correct`. Earliest is the first row for that learning-unit id and mode, not the first row for a position.
- The denominator is `len(pass_items_for(generation definitions))`. It is not `COUNT(practice_pass_items)`, not the attempt-row count, and not the session item count after a round is appended.
- `list_attempt_records_for_lesson` returns that opening size in `pass_item_count` on every fresh read, including a new repository connection after the append. The current `COUNT(*)` grouped by session is the bug: an 8-item pass plus the two still-uncorrected copies would reload as 6/10. After the fix it stays 6/8.
- `corrected`, later `incorrect` rows, and repeat-round attempts do not change the numerator or the denominator.
- Example: 8 items, 6 first-try correct, 2 first-try incorrect, and 1 of those 2 later `corrected`. The score stays `6/8` after the correction and after the remaining item returns in the next round. The history shows Incorrect for the first row and Corrected for the later row.
- A pass with no retries and one attempt per item keeps the same fraction as today.
- A pass item is one mode of one phrase: Choice or Typed, not the phrase as a whole.
- An item is uncorrected when this session has an `incorrect` attempt for that learning-unit id and mode and has no `correct` or `corrected` attempt for that same pair. The lookup ignores position. A first-try `correct` item is not in the queue. An item that was never attempted is not an error and is not in the queue.
- An appended row copies `learning_unit_id`, `mode`, and `definition_id` from the opening item. It does not mint a learning unit. Its new position is only where the cursor sits. Queue membership, the corrected remap, and the first-try score all use the pair. A match submitted on the copy finds the original `incorrect` row and is stored as `corrected`. The next queue build then omits that pair.
- A self-produced match removes that item. That includes a first-try `correct` and a `corrected` row after Try again. Show answer writes no attempt, so it does not remove the item.
- Choice and Typed are separate. A `corrected` Choice does not remove Typed. A Show answer on Choice does not pull Typed into the queue when Typed was first-try correct.
- Rounds continue until that queue is empty. There is no Practice missed phrases control.
- The next round is appended to the same open session. Continue past the last item of the current round, in one transaction: if the queue is non-empty, append those items, set the cursor to the first appended item, and return that item. The focus view stays open. Feedback is not shown. If the queue is empty, the cursor passes the last item and the existing exhausted-session finish runs.
- A second Continue for the position that already started the round does not append another copy and does not skip the first item of the new round.
- The appended item is a fresh card. The hint is closed: no grade, no expected phrase, and the previous position's reveal flag is not copied.
- Exit Practice does not append, even when the queue is non-empty.

### Grade card

- Paint one result word: Correct, Incorrect, or Corrected.
- Paint the learner's submitted text once on Incorrect and Corrected.
- Do not paint `expected` until Show answer. Do not paint `chunks_used`, `chunks_missed`, or a second copy of the same phrase.
- The incorrect explanation stored on the row must not contain the expected phrase. The row still stores `expected` for Show answer and for history.
- History rows keep the unit jump and the explanation. They do not gain a new page.
