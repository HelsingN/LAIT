## Phase Goal

**Goal:** A learner can launch the local application and complete a source-to-feedback Gap Fill workflow, while maintainers can observe that it runs through documented public contracts.

This follow-up covers only UX-16 and UX-17. Diagnosis: `.planning/phases/01-mod-first-manual-learning-loop/01-13-DIAGNOSIS.md`.

**As a** learner, **I want** a reload to bring back the ready exercise set and the saved attempts, and the last Continue to end this pass, **so that** I am not sent through Generate again and I do not sit on an empty practice screen.

<objective>
Add two read queries and close the open session when its cursor is past the last item. Hydrate Practice and Feedback from those reads. Keep the just-finished session separate from older history.
Purpose: React state was the only copy the UI reloaded, while SQLite already held the generation and the attempts.
Output: `exercise.latest_completed`, `attempt.list_for_lesson`, load-time hydration, and finish-on-last-continue.
</objective>

## Decisions

### Read API

Both are application queries. HTTP maps DTOs and calls `handle`. It does not compare id sets and it does not classify a pass. Names join the D-23 boundary the same way `lesson.get` and `practice.get` already do. No new command. `practice.finish` stays the close.

`exercise.latest_completed`

- Query module: `backend/lait/application/queries/exercise_latest_completed.py`
- `QUERY_NAME = "exercise.latest_completed"`
- HTTP: `GET /api/lessons/{lesson_id}/exercises/latest`
- `operation_id`: `exercise.latest_completed`
- Handler inputs: `lesson_id`, the existing repository port.
- Handler reads `latest_completed_generation(lesson_id)` and the current accepted ids (`list_units`, status accepted, `removed_at` null), same tuple comparison `practice.start` already uses: `tuple(sorted(ids))`.
- Response DTO:

```text
restorable: bool
generation_id: str | null
accepted_unit_ids: list[str]
```

- `restorable` is true only when a completed generation exists and that sorted tuple equals the current accepted tuple. Then `generation_id` and `accepted_unit_ids` are that generation's values.
- Otherwise `restorable` is false, `generation_id` is null, and `accepted_unit_ids` is empty. A stale generation is not returned. Unknown lesson is the same not-found error `lesson.get` already uses.
- Missing generation is 200 with `restorable: false`, not a 404. The workspace must still render.

`attempt.list_for_lesson`

- Query module: `backend/lait/application/queries/attempt_list_for_lesson.py`
- `QUERY_NAME = "attempt.list_for_lesson"`
- HTTP: `GET /api/lessons/{lesson_id}/attempts`
- `operation_id`: `attempt.list_for_lesson`
- Repository returns attempt rows joined to their session: `session_id`, `session_status`, `cursor`, pass-item count, `mode`, and the attempt fields the workspace already shows (`attempt_id`, `category`, `submitted`, `expected`, `explanation`, `unit_text`, `span_start`, `span_end`, `created_at`). Order is session `created_at`, then attempt `created_at`, then ids.
- The query, not the router, sets `session_disposition`:
  - `completed` — `closed` and `cursor >= pass_item_count`
  - `exited` — `closed` and `cursor < pass_item_count`
  - `abandoned` — `abandoned`
  - `open` — `open`
- Response DTO is `{ attempts: [ ... ] }` including `session_id`, `session_disposition`, and `mode` on each row. No `used` / `missed` redesign. Those fields may be omitted from this DTO. Slice 4 owns the card.

Declare `latest_completed_generation` and `list_attempt_records_for_lesson` on `LearningUnitRepository`. Implement them on the SQLAlchemy repository. No new table and no Alembic revision.

Regenerate the TypeScript client (`export_openapi`, then `npm --prefix frontend run openapi:generate`) so `lessonApi.ts` calls the generated functions. Operation ids stay the query names.

### When the pass ends

Do not add `practice.complete`. The last Continue already calls `practice.get`. If that view is `open` and `current` is null, call the existing `practice.finish`, then leave Focus Practice. That close unfreezes units because no open row remains. Show a minimal summary of that `session_id` only.

The same rule applies on load when the stored `lait.practice-session.{lessonId}` points at an open session whose `practice.get` has `current: null`. Finish it and show that session. Do not mount the empty Focus shell.

Exit Practice stays `practice.finish` at the current cursor. If the cursor is still below the pass length, `attempt.list_for_lesson` reports `exited`. The summary says this pass was left early. It does not say the pass was completed.

A new Start Practice still creates a new session through `practice.start`. Its attempts use the new `session_id`. The summary of the pass just finished keeps the old id. Earlier sessions render under a separate "Earlier passes" heading. This slice does not resume a closed session and does not add retry after an incorrect answer.

### practice.finish errors on an exhausted session

An exhausted session is an open row whose `practice.get` returns `current: null` because `cursor` is already past the last pass item. The client calls the existing `practice.finish` for that `session_id` only. It does not invent a second close command.

- Finish returns the closed view: clear `lait.practice-session.{lessonId}`, leave Focus, reload `attempt.list_for_lesson`, and show the summary for that `session_id` only. Units unlock because the row is no longer open.
- Finish returns 404 (`PracticeSessionNotFoundError`: missing id, or the row is already `closed` or `abandoned`): the close already happened or the id is gone. Clear the stored open id, leave Focus, and reload the attempt list. If that list still contains the id, show its disposition. Do not start a new session and do not call `exercise.generate`. Do not keep the empty Focus shell.
- Finish fails with a network error or a 5xx: the row may still be open. Keep the stored id. Stay out of a fake completed summary. Show `Could not finish this practice. Try again.` and retry the same `practice.finish`. Do not clear the id and do not enable unit edits while that retry is outstanding.
- Finish succeeded and the following attempt-list request failed: the session is already closed. Show `Could not load practice history. Try again.` and retry only the list. Do not call `practice.finish` again for that success.

`practice.finish` itself stays as it is: a non-open row raises `PracticeSessionNotFoundError`. This plan does not turn that into a 200.

Load and reload call `exercise.latest_completed` and `attempt.list_for_lesson`. They do not call `exercise.generate`. When `restorable` is true, Practice unlocks and Start Practice stays the existing start command. When `restorable` is false, Practice stays locked until the learner generates for the new accepted set.
