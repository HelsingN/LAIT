## Происхождение и границы

Файл пересоздан локально по текущей переписке с явного согласия пользователя. Это не побайтовая копия исходного артефакта из предыдущего ChatGPT-чата: доступно его описание, но не содержимое. Ниже отделены наблюдения пользователя, непосредственная проверка браузером и предварительные предложения.

Пользователь сообщил, что прошёл функциональный сценарий на одном уроке: формально всё работает, но текущий интерфейс неудобен для реального использования. Это пользовательская оценка, а не повторная функциональная проверка агентом. В предыдущем чате упоминались reopen/source и stale practice session; их текущий статус здесь не подтверждён, и они не записаны как заново воспроизведённые баги.

Аудит не закрывает Phase 1, не заменяет blocking-human checkpoint и не означает `approved`. Классификация и предлагаемая фаза ниже предварительные; перенос в план, реализация, commit и push требуют отдельного указания пользователя.

- Область: Lessons и workspace урока.
- Тип: visual / UX debt. Важность: major для урока, minor для списка уроков.
- Наблюдение: на широком экране содержимое остаётся узкой центральной колонкой с большими пустыми полями. Начальная страница устраивает пользователя в узком окне; проблема особенно заметна в уроке.
- Проверка: браузер при viewport 1535 × 656 показал ширину панелей около 637 px; на скриншоте пользователя также видны широкие поля.
- Воспроизведение: открыть страницу и развернуть окно на широкий экран.
- Ожидание: рабочее пространство урока использует доступную ширину; основной текст и выбранные фразы можно видеть одновременно без чрезмерно длинных строк текста.
- Предлагаемая фаза: Phase 1 UX follow-up, после согласования объёма.
- Доказательство: E1, непосредственная проверка браузером.

- Ожидание: текущий этап и основные действия видны в пределах окна; длинное содержимое может прокручиваться внутри своей области.

### UX-06 — заголовок секции Generate Exercises неотличим от обычной надписи

- Область: переход к генерации упражнений.
- Тип: UX debt / visual / workflow. Важность: major.
- Наблюдение: Generate Exercises снаружи — интерактивный заголовок сворачиваемой секции, а не команда генерации. Пользователю не очевидны возможность раскрытия и текущее состояние секции. Ниже Practice и Feedback также выглядят обычными надписями. Общая проблема раскрытия описана в UX-07; UX-06 фиксирует её проявление на этапе генерации.
- Исправление раннего вывода от 2026-10-02: формулировка «кнопка создаёт ещё одну кнопку» была неточной. Внутренняя кнопка уже является действием секции и становится видимой при её раскрытии. Внешний заголовок переключает видимость содержимого; повторное нажатие сворачивает его. Семантическая роль button в браузере относится к управлению раскрытием и не означает запуск генерации.
- Дополнительная неоднозначность: заголовок секции и внутренняя команда имеют одинаковый текст Generate Exercises (E5). Это может создавать ожидание немедленного запуска при клике на заголовок. Наличие отдельного действия внутри раскрываемой секции само по себе не является дефектом; два клика не классифицируются как ошибка без оценки всей модели взаимодействия.
- Воспроизведение: прокрутить урок до Generate Exercises → нажать надпись → увидеть раскрытый блок с одноимённой кнопкой. Реальная генерация и её результат в этом уточнении агентом не проверялись.
- Ожидание: понятно, как открыть этап и какое действие создаёт упражнения; видны доступность и следующий шаг.
- Предлагаемая фаза: Phase 1 UX follow-up.
- Доказательство: E4, E5, уточнения пользователя и непосредственная проверка раскрытия/сворачивания в UX-07.

### UX-07 — свёрнутые секции не показывают, что содержимое скрыто

- Область: Source, Learning Units, Generate Exercises; общая модель этапов workspace.
- Тип: UX debt / workflow / visual. Важность: major.
- Наблюдение пользователя: после сворачивания трёх секций остаются обычные надписи; неочевидно, что они управляют показом содержимого. Пользователь только сейчас обнаружил повторное нажатие для сворачивания и предположил, что ранее невидимый Source мог быть просто свёрнут.
- Непосредственная проверка агентом от 2026-10-02: исходно Source, Learning Units и Generate Exercises были collapsed. Для каждой секции отдельно выполнено нажатие на заголовок, получено expanded и видимое содержимое, затем повторное нажатие вернуло collapsed и скрыло содержимое. Source показал полный текст, Learning Units — четыре accepted units, Generate Exercises — `gap-fill` и отдельную одноимённую кнопку генерации. Все три секции возвращены в исходное свёрнутое состояние. Генерация не запускалась, юниты не менялись.
- Practice и Feedback в этой проверке disabled; их раскрытие не проверялось.
- Воспроизведение: нажать заголовок Source → увидеть текст → нажать повторно → текст исчезает; повторить с Learning Units и Generate Exercises.
- Ожидание: явно видны интерактивность заголовка и состояние раскрытия/сворачивания, например стрелка и понятное оформление строки. Скрытое содержимое не воспринимается как отсутствующее или потерянное. Само сворачивание работает; замечание касается понятности управления.
- Гипотеза о прежнем Source: сворачивание является возможным объяснением, но причина исторического случая не подтверждена. Не закрывать прежние reopen/persistence bugs на основании этой проверки.
- Предлагаемая фаза: Phase 1 UX follow-up.
- Доказательство: E6 и непосредственная проверка браузером; UX-06 дополнительно подтверждён раскрытием секции генерации.

### UX-08 — после генерации технический статус и слабый переход к практике

- Область: завершение Generate Exercises → Practice.
- Тип: UX debt / workflow / visual. Важность: major.
- Наблюдение пользователя: после запуска генерации предыдущий блок остаётся с `gap-fill`, кнопкой Generate Exercises и отдельной надписью `completed`; ниже появляется раскрытый блок Practice с кнопкой Start Practice. Пользователь воспринимает `completed` как служебный вывод режима отладки.
- Доказательство на скриншоте E7: видны оба блока и обе кнопки одновременно, а также `completed`. Последовательность запуска описана пользователем; агент не запускал повторную генерацию и не проверял поведение повторного нажатия.
- Воспроизведение: раскрыть Generate Exercises → нажать внутреннюю кнопку генерации → дождаться результата → увидеть прежний блок с `completed` и следующий блок Start Practice.
- Ожидание: результат объяснён языком урока, например «Упражнения готовы», а начало практики становится очевидным следующим действием. Если показывается число упражнений, оно должно опираться на реальные данные; в этой проверке число не установлено.
- Уточнение пользователя от 2026-10-02: повторная успешная генерация имеет смысл только после изменения юнитов; при тех же юнитах упражнение будет таким же. Для текущего сценария после успешной генерации неизменённого набора юнитов не предлагать повторную генерацию как полезное следующее действие. Изменение набора юнитов, используемого для упражнений, должно делать необходимость обновления понятной пользователю. Это ожидаемое UX-поведение по указанию пользователя; идентичность результатов повторного запуска агентом отдельно не проверена. Повторная попытка после ошибки — другой сценарий, здесь не проверенный.
- Ограничение вывода: сохранение блока генерации само по себе не является функциональным багом. Замечание относится к техническому тексту, иерархии действий и растущей вертикальной цепочке этапов (связь с UX-02). Конкретное решение — сворачивание, замена содержимого или другая компоновка — пока не утверждено.
- Предлагаемая фаза: Phase 1 UX follow-up.
- Доказательство: E7, сообщение пользователя.

- Подтверждение пользователя от 2026-10-02: «вообще не очевидно, куда вводить ответ: то ли в само предложение, то ли ниже, то ли ещё куда-то». Неясное расположение области ввода мешает даже начать отвечать; это подтверждённое пользователем UX-затруднение, а не только предположение агента по снимку.
- Проверка ввода агентом: при вводе I was responsible for upgrading текст появился в отдельном поле под предложением, а при фокусе стали видны границы поля; Submit Answer активировалась. Этот правильный typed-ответ не отправлялся: по просьбе пользователя он заменён на неправильную фразу для проверки ошибки (UX-10).
- Воспроизведение: дать четыре правильных ответа выбором плиток → Continue после четвёртого → увидеть первое предложение без вариантов.
- Ожидание: явно обозначить новый этап («Теперь введите фразу по памяти» или эквивалент), обеспечить различимое поле ввода с понятными границами и связью с пропуском, указать место ввода и показать прогресс. Встроенное в предложение поле или отдельное поле с подписью — варианты решения, конкретное расположение пока не выбрано.
- Ограничение: ввод и отправка typed-ответов ещё не проверены; это UX-замечание к переходу, не подтверждение ошибки последовательности упражнений.
- Предлагаемая фаза: Phase 1 UX follow-up.
- Доказательство: непосредственная проверка браузером и просмотр снимка после перехода; отдельный файл снимка не сохранён.

### UX-13 — после ошибки ответ редактируется, но повторно не проверяется

- Область: typed Gap Fill, исправление неправильного ответа.
- Тип: UX debt / workflow. Важность: major.
- Проверка агентом 2026-10-02 по просьбе пользователя: после incorrect для I was responsible for testing поле Answer заменено на правильное I was responsible for upgrading. Поле приняло изменение, но Submit Answer не появился; остался Continue, а обратная связь по-прежнему показывала incorrect и первоначальную ошибочную фразу. Enter в поле не изменил видимый экран или оценку. После Continue открылось следующее предложение The alarms * ______ * one of the sensor controllers repeatedly disconnecting from the network. Поле Answer пустое, Submit Answer disabled.
- Воспроизведение: отправить ошибочную фразу → исправить её в том же поле → попробовать Enter → нажать Continue.
- Наблюдение: интерфейс допускает редактирование уже оценённого ответа, не предоставляя понятной повторной проверки. Видимый текст поля расходится с текстом в неизменившейся обратной связи. Переход дальше не проверяет исправление.
- Ожидание для обсуждения: либо явная повторная попытка с понятными правилами учёта результата, либо неизменяемый показ отправленного ответа и объяснённый переход дальше. Если предполагается отдельное закрепление правильной фразы после ошибки, его нужно обозначить как отдельное действие. Модель повторных попыток пока не утверждена; отсутствие retry не объявляется нарушением спецификации без её проверки.
- Ограничение: проверено поведение интерфейса; число записей попыток в БД и возможное повторение ошибочного юнита позже не проверены.
- Предлагаемая фаза: Phase 1 UX follow-up; изменения учебной модели согласовать отдельно.
- Доказательство: непосредственная проверка браузером.

### UX-14 — подтверждение Start Over остаётся открытым при продолжении ответа

- Область: Focus Practice, подтверждение перезапуска.
- Тип: UX debt / workflow. Важность: major (предварительно).
- Проверка агентом 2026-10-02: на втором typed-задании нажата внешняя кнопка Start Over. Под текущим заданием появился встроенный блок с сообщением `Start over: Abandon this practice run and start a new session on the same units? Submitted answers stay saved.` и второй кнопкой Start Over. Отдельной кнопки отмены в видимом интерфейсе нет. Внутренняя кнопка подтверждения не нажималась.
- По следующему указанию пользователя, при открытом блоке введено indicated that и нажато Submit Answer. Ответ принят как correct, появилась Continue. Блок подтверждения с второй кнопкой Start Over остался открытым. Сам ввод и отправка не блокируются.
- Воспроизведение: Start Over → не подтверждать → ввести правильный ответ на текущее задание → Submit Answer → увидеть результат и прежний блок подтверждения одновременно.
- Ожидание: понятно, как отказаться от перезапуска и продолжить текущий проход. Нужна явная отмена/закрытие либо согласованное снятие ожидающего подтверждения при продолжении практики. Подтверждение само по себе полезно; немодальное оформление не объявляется ошибкой без требований к взаимодействию.
- Ограничение: фактический перезапуск, сохранность отправленных ответов, повторный клик по внешней кнопке и поведение блока после Continue ещё не проверены. Сообщение о сохранении ответов — текст интерфейса, не проверенный факт о БД.
- Предлагаемая фаза: Phase 1 UX follow-up.
- Доказательство: непосредственная проверка браузером и просмотр снимков до и после отправки; отдельные файлы снимков не сохранены.

### UX-15 — после выхода результаты находятся вне текущего видимого экрана

- Область: Exit Practice → workspace / Feedback.
- Тип: UX debt / workflow. Важность: major (предварительно).
- Проверка агентом 2026-10-02: после correct на втором typed-задании и при открытом подтверждении Start Over нажата Exit Practice. Без дополнительного подтверждения показан workspace того же урока и по тому же URL. Source, Learning Units, Generate Exercises, Practice и Feedback expanded; в Practice доступна Start Practice, кнопки Delete в списке юнитов доступны. Фактическое редактирование юнитов не выполнялось. Подтверждение Start Over и служебная надпись о блокировке юнитов больше не видны.
- Наблюдение: в текущем viewport после выхода видны начало workspace и Source, а список результатов Feedback расположен ниже, вне экрана. Явного видимого итога выхода или перехода к результатам не обнаружено. Пользователь должен прокрутить страницу, чтобы увидеть обратную связь.
- Feedback содержит семь видимых строк попыток: пять correct и две incorrect. Шесть отправок непосредственно наблюдались агентом в текущем проходе; происхождение дополнительной incorrect-строки (`indicated that` вместо `I was responsible for upgrading`) отдельно не установлено. Не считать это доказательством лишней/дублирующей записи или результата Enter без дальнейшей проверки.
- Ожидание для обсуждения: после выхода дать понятное подтверждение завершения/выхода и доступ к результатам либо к дальнейшему действию без поиска по длинному workspace. Выбор целевого экрана зависит от назначения Exit и пока не согласован.
- Ограничение: сохранность результатов после reload, возможность продолжить тот же проход и фактический Start Over не проверены. Наличие результатов в текущем Feedback не является проверкой хранения в БД.
- Предлагаемая фаза: Phase 1 UX follow-up; связано с UX-02.
- Доказательство: непосредственная проверка браузером и просмотр снимка после Exit Practice; отдельный файл снимка не сохранён.

### UX-16 — после reload не восстанавливаются Feedback и готовность к практике

- Область: workspace после Exit Practice и перезагрузки страницы.
- Тип: bug (наблюдаемое невосстановление состояния UI) / workflow. Важность: major, высокий приоритет диагностики.
- Проверка агентом 2026-10-02: до reload в Feedback было семь строк результатов, Practice раскрыта с Start Practice, генерация показывала completed. После reload по тому же URL Source и четыре accepted units сохранились, но Feedback стал disabled/collapsed без результатов, Practice disabled/collapsed без Start Practice, completed исчез. Generate Exercises оставалась доступной. Для продолжения проверок пришлось повторно сгенерировать упражнения при неизменённых юнитах.
- Воспроизведение: сгенерировать упражнения → начать практику → отправить ответы → Exit Practice → убедиться в Feedback → reload.
- Ожидание: ранее доступные результаты и состояние готовых упражнений восстанавливаются либо интерфейс явно объясняет ограничения и способ доступа к истории. Не заставлять повторно генерировать идентичные упражнения только из-за обновления страницы.
- Ограничение: не установлено, исчезли ли данные в БД или только не загружаются в UI. Не заявлять потерю сохранённых данных без отдельной диагностики. Перезапуск Docker и браузера не проверены.
- Предлагаемая фаза: Phase 1 follow-up, диагностика persistence/reopen перед расширением дизайна.
- Доказательство: сравнение непосредственных состояний браузера до и после reload.

### UX-17 — полное прохождение заканчивается пустым экраном без итога

- Область: Focus Practice после последнего Continue.
- Тип: bug / UX debt / workflow. Важность: major, высокий приоритет.
- Проверка агентом: после подтверждённого Start Over пройдены четыре задания выбором фразы и четыре вводом по памяти; все восемь результатов correct. После Continue последнего typed-задания исчезли предложение, поле и обратная связь. Остались только `Learning units are locked while practice is open. Exit Practice to edit them.`, Exit Practice и Start Over. Повторное чтение состояния подтвердило этот экран.
- Воспроизведение: пройти 4 choice + 4 typed задания → Continue после последнего ответа.
- Ожидание: явное завершение и итог текущего прохода, понятное следующее действие. Завершившийся набор заданий не должен выглядеть как пустая или зависшая практика.
- Проверка recovery: Exit Practice вернула workspace и Feedback с девятью correct-строками (одна до Start Over плюс восемь после него). Данные видны в текущем UI; сохранность после reload не подтверждена (см. UX-16).
- Ограничение: состояние сессии в БД и причина пустого экрана не диагностировались.
- Предлагаемая фаза: Phase 1 follow-up.
- Доказательство: непосредственное прохождение и просмотр снимка пустого экрана; отдельный файл снимка не сохранён.

## Итоги заключительных проверок

1. Reload: текст и юниты сохранены в UI, Feedback и готовность практики не восстановлены (UX-16).
2. Start Over: внешняя кнопка показала подтверждение; внутренняя подтверждена в рамках согласованной проверки. Со второго задания интерфейс вернулся к первому с плитками и пустым выбором; подтверждение исчезло. Одна отправленная до перезапуска попытка осталась видна в Feedback после последующего выхода. Это проверка текущего UI, не хранения после reload.
3. Полный проход: четыре ответа выбором и четыре вводом приняты correct; после последнего Continue пустой Focus Practice (UX-17). Для выхода понадобилась Exit Practice.
4. Start Practice после Exit без reload: после полного прохода стартовало первое задание с плитками. Дополнительно отправлен первый правильный ответ, выполнен Continue ко второму, Exit и снова Start Practice — опять первое задание, не возобновление второго. В конце выполнен Exit без ответа в последнем запуске. Название Exit следует согласовать с этим завершением, а не обещать паузу/продолжение.
5. Feedback после этих проверок: десять correct-строк — одна до Start Over, восемь полного нового прохода и одна повторного запуска. История показана плоским списком, без визуального разделения сессий и choice/typed. Предыдущие семь строк исчезли из UI после reload; их наличие в БД не проверено.

## Приоритеты и предложенный формат Feedback

- Приоритет 1: диагностировать и исправить невосстановление результатов/готовности после reload (UX-16), сделать явное завершение практики (UX-17). Оба наблюдения воспроизведены; причины и соответствие точным требованиям требуют проверки кода перед исправлением.
- Приоритет 2: рабочая компоновка по ширине/высоте окна, компактные юниты и доступное добавление (UX-01–05); очевидные раскрывающиеся секции и переход к практике (UX-06–08).
- Приоритет 3: понятный переход к вводу и различимое поле (UX-12); согласованная модель исправления/повторной попытки (UX-13); отмена Start Over (UX-14); краткая обратная связь и видимые результаты (UX-10, UX-15); порядок вариантов без подсказки ответа (UX-09).
- Отложено пользователем: drag and drop (UX-11), номер будущей фазы не выбран.

Предложение по Feedback для обсуждения: показывать сводку текущего прохода с явным признаком «завершён / прерван», отдельно результаты выбора и воспроизведения по памяти, трудные фразы и понятное следующее действие. Подробную историю раскрывать отдельно и группировать по сессиям. Ошибка отображается одной парой «Ваш ответ → ожидаемая фраза», по возможности с выделением различий, без used/missed и повторных копий ответа. «Повторить трудные фразы» — предложение новой учебной возможности, а не утверждение, что она уже существует или входит в Phase 1. Формат и реализация не утверждены.

## Предложения для обсуждения

Это варианты решения, а не согласованный план реализации:

1. На широком экране разместить Source слева, компактный список Learning Units справа.
2. Организовать рабочую область по высоте окна; прокручивать длинный текст и список внутри соответствующих панелей.
3. Показывать каждую выбранную фразу один раз; убрать отдельные строки служебного статуса там, где они не помогают пользователю.
4. Предоставить компактное удаление выбранного юнита, включая доступ с клавиатуры.
   - Уточнение пользователя: компактные плитки вариантов в практике визуально подходят как ориентир для списка на странице подготовки. При выборе юнита показывать крестик удаления. Это положительная оценка текущей плотности вариантов, а не требование копировать их поведение выбора ответа.
5. Держать добавление рядом с выделением либо на постоянно видимой панели над списком.
6. Разделить название этапа, управление его раскрытием и заметную кнопку создания упражнений. Рассмотреть переключение между подготовкой и практикой вместо длинной цепочки секций.
